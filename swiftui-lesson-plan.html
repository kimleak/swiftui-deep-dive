SwiftUI Deep Dive: A 12-Week Plan for UIKit Engineers

A project-driven curriculum modeled on the KSHRD Advanced iOS course, redesigned for someone who already knows UIKit. Each week pairs a UIKit-to-SwiftUI mental-model bridge with full, copy-pasteable SwiftUI code and a hands-on project. By Week 12 you ship a multi-module SwiftUI app with networking, persistence, animations, and tests.

Level: Intermediate → Advanced Tooling: Xcode 16, iOS 17/18 SDK ~10 hrs/week Prereq: Swift 5.9+, UIKit fundamentals
★

How to use this plan

Read this first — it'll save you a week.

Each module follows the same shape: a UIKit → SwiftUI bridge (so you map what you know), core concepts (the new mental model), full code samples (drop into a Playground or new SwiftUI app), a weekly project with concrete acceptance criteria, and further reading.

Treat the project as the assessment. If you can ship it without copying the sample code line-for-line, you've actually learned the module.

Pro tip: Build every weekly project in a single Xcode workspace called SwiftUIBootcamp with each week as a Swift Package or app target. By Week 12 you'll have a portfolio of 11 mini-apps.

Week 1 · Mental Model: Views Are Values

Stop thinking like a UIView subclass. Start thinking like a function from State → UI.

1.1The single biggest UIKit-to-SwiftUI shift

In UIKit, a view is a long-lived object you mutate (label.text = "Hi"). In SwiftUI, a View is a value — a lightweight struct that the framework re-creates from your state. The framework diffs that tree and updates the screen. You never hold or mutate a view; you describe what should be on screen for the current state.

UIKit (imperative)
class CounterVC: UIViewController {
    private let label = UILabel()
    private var count = 0 {
        didSet { label.text = "\(count)" }
    }
    @objc func tap() { count += 1 }
}
SwiftUI (declarative)
struct CounterView: View {
    @State private var count = 0
    var body: some View {
        VStack(spacing: 16) {
            Text("\(count)").font(.largeTitle)
            Button("Tap") { count += 1 }
        }
    }
}

1.2The four key primitives you'll see everywhere

  • View — protocol; conform with a body property returning some View.
  • @State — owned, mutable, view-local state. Like private var with diffing.
  • @Binding — a two-way handle to state owned by a parent. Like inout for views.
  • some View — opaque return type; lets the compiler reason about the view tree without erasing types.

1.3Modifiers compose, they don't mutate

In UIKit you'd write label.font = .boldSystemFont(...). In SwiftUI, modifiers return a new wrapped view. Order matters.

Text("Hello, SwiftUI")
    .font(.title)
    .foregroundStyle(.white)
    .padding()
    .background(.blue, in: RoundedRectangle(cornerRadius: 12))
    .padding()
Gotcha: .padding().background() ≠ .background().padding(). Modifiers wrap outward — the second pads outside the background. Internalize this early.

1.4Previews replace your simulator loop

#Preview("Counter") {
    CounterView()
        .preferredColorScheme(.dark)
}

#Preview("Counter — Long Label") {
    CounterView()
        .environment(\.locale, .init(identifier: "de_DE"))
}

Week 2 · Layout System

Stacks, frames, alignment, and why GeometryReader isn't your first choice.

2.1The layout protocol in one paragraph

SwiftUI layout is a negotiation. The parent proposes a size to the child; the child returns a desired size; the parent positions it. There is no Auto Layout solver, no constraints. Once you grok this, layout bugs become obvious.

2.2The stack family

VStack(alignment: .leading, spacing: 12) {
    Text("Title").font(.title2.bold())
    Text("Subtitle").foregroundStyle(.secondary)
    HStack {
        Image(systemName: "star.fill").foregroundStyle(.yellow)
        Text("4.8")
        Spacer()                  // pushes everything left
        Text("12 reviews").foregroundStyle(.secondary)
    }
}
.padding()
.frame(maxWidth: .infinity, alignment: .leading)
.background(.regularMaterial, in: RoundedRectangle(cornerRadius: 16))
UIKit equivalent
// UIStackView with axis = .vertical
// Plus a UIStackView nested for the rating row
// Plus constraints for padding, maxWidth, etc.
// ~30 lines to express the same idea.
SwiftUI
VStack(alignment: .leading, spacing: 12) { /* … */ }
    .padding()
    .frame(maxWidth: .infinity, alignment: .leading)

2.3Frame, fixedSize, and the layout neutral

// .frame proposes a size; the view may not honor it.
Text("Long body of text that wraps")
    .frame(width: 120)            // proposes 120pt width; text wraps
    .border(.red)

// fixedSize tells a view: "use your ideal size, ignore the proposal"
Text("Long body of text that should not truncate")
    .fixedSize(horizontal: false, vertical: true)

2.4Alignment guides (the "Auto Layout moment")

HStack(alignment: .lastTextBaseline) {
    Text("Hello").font(.largeTitle)
    Text("world").font(.body).foregroundStyle(.secondary)
}
When to reach for GeometryReader: almost never as a layout container. Use it inside a .background or .overlay to read a size, or use the new Layout protocol (iOS 16+) for genuinely custom layouts.

2.5Custom layouts with the Layout protocol

struct EqualWidths: Layout {
    func sizeThatFits(proposal: ProposedViewSize, subviews: Subviews, cache: inout ()) -> CGSize {
        let w = proposal.width ?? 0
        let each = w / CGFloat(max(subviews.count, 1))
        let h = subviews.map { $0.sizeThatFits(.init(width: each, height: nil)).height }.max() ?? 0
        return CGSize(width: w, height: h)
    }
    func placeSubviews(in bounds: CGRect, proposal: ProposedViewSize, subviews: Subviews, cache: inout ()) {
        let each = bounds.width / CGFloat(max(subviews.count, 1))
        for (i, sv) in subviews.enumerated() {
            sv.place(at: CGPoint(x: bounds.minX + each * CGFloat(i), y: bounds.minY),
                     proposal: .init(width: each, height: bounds.height))
        }
    }
}

Week 3 · State & Bindings

@State, @Binding, @Observable — when to use which, and the iOS 17 Observation revolution.

3.1The state ownership rule

Every piece of state has exactly one owner. Pass a read-write handle (@Binding) downward, never duplicate. If two views need to read/write the same value, lift the state to their common parent.

3.2@State, @Binding

struct ToggleRow: View {
    @Binding var isOn: Bool        // owned by parent
    let label: String
    var body: some View {
        Toggle(label, isOn: $isOn) // $ creates a Binding
    }
}

struct SettingsView: View {
    @State private var notifications = true       // owner
    @State private var darkMode = false
    var body: some View {
        Form {
            ToggleRow(isOn: $notifications, label: "Notifications")
            ToggleRow(isOn: $darkMode, label: "Dark mode")
        }
    }
}

3.3@Observable (iOS 17+) — the new way

import Observation

@Observable
final class CartModel {
    var items: [String] = []
    var total: Decimal = 0
    func add(_ name: String, price: Decimal) {
        items.append(name)
        total += price
    }
}

struct CartView: View {
    @State private var cart = CartModel()         // owns it
    var body: some View {
        VStack {
            Text("Total: \(cart.total, format: .currency(code: "USD"))")
            List(cart.items, id: \.self) { Text($0) }
            Button("Add coffee") { cart.add("Coffee", price: 4.5) }
        }
    }
}
Don't use ObservableObject + @Published + @StateObject for new code on iOS 17+. The @Observable macro reads only the properties your view actually uses, so re-renders are surgical. The old protocol re-renders any view holding the object whenever any @Published changes.

3.4@Bindable — bind into an @Observable model

struct EditProfile: View {
    @Bindable var user: UserModel  // user is @Observable
    var body: some View {
        Form {
            TextField("Name", text: $user.name)
            DatePicker("DOB", selection: $user.dob, displayedComponents: .date)
        }
    }
}

3.5Decision tree

  • Local-only, simple value? → @State
  • Read/write a parent's @State? → @Binding
  • Reference type with multiple properties / business logic? → @Observable + @State at the owning view
  • Pass an @Observable deep without prop-drilling? → @Environment (Week 8)

5.2The four flavors of animation

// 1. Implicit on a value
.animation(.smooth, value: isExpanded)

// 2. Explicit, scoped to a state change
withAnimation(.spring(response: 0.4, dampingFraction: 0.75)) {
    isExpanded.toggle()
}

// 3. Transition (insertion/removal)
if showDetails {
    DetailsView().transition(.move(edge: .bottom).combined(with: .opacity))
}

// 4. matchedGeometryEffect — hero animations
@Namespace private var ns
struct CardView: View {
    @State private var open = false
    var body: some View {
        if open {
            VStack { /* expanded */ }
                .matchedGeometryEffect(id: "hero", in: ns)
                .onTapGesture { withAnimation(.spring) { open = false } }
        } else {
            RoundedRectangle(cornerRadius: 12)
                .frame(height: 80)
                .matchedGeometryEffect(id: "hero", in: ns)
                .onTapGesture { withAnimation(.spring) { open = true } }
        }
    }
}

5.3Phase animations (iOS 17+)

Image(systemName: "heart.fill")
    .symbolEffect(.bounce, value: likes)
    .phaseAnimator([1.0, 1.2, 0.95, 1.0], trigger: likes) { content, scale in
        content.scaleEffect(scale)
    }
Animation rule of thumb: reach for withAnimation first. Use implicit .animation(_:value:) only when one specific value drives a specific view's change.

Week 6 · Concurrency & Networking

async/await, structured concurrency, and the .task modifier — your new URLSession workflow.

6.1The .task modifier — your most-used networking entry

struct UserListView: View {
    @State private var users: [User] = []
    @State private var error: Error?
    var body: some View {
        List(users) { Text($0.name) }
            .overlay { if users.isEmpty { ProgressView() } }
            .task {                                          // runs when view appears
                do { users = try await UserAPI.fetchAll() }
                catch { self.error = error }
            }
    }
}

6.2An async API client

struct User: Codable, Identifiable { let id: Int; let name: String; let email: String }

enum APIError: Error { case badStatus(Int), decoding(Error) }

struct UserAPI {
    static let baseURL = URL(string: "https://jsonplaceholder.typicode.com")!
    static func fetchAll() async throws -> [User] {
        let (data, resp) = try await URLSession.shared.data(from: baseURL.appending(path: "users"))
        guard (resp as? HTTPURLResponse)?.statusCode == 200 else {
            throw APIError.badStatus((resp as? HTTPURLResponse)?.statusCode ?? -1)
        }
        do { return try JSONDecoder().decode([User].self, from: data) }
        catch { throw APIError.decoding(error) }
    }
}

6.3Structured concurrency with TaskGroup

func fetchAvatars(for users: [User]) async throws -> [Int: Data] {
    try await withThrowingTaskGroup(of: (Int, Data).self) { group in
        for user in users {
            group.addTask {
                let url = URL(string: "https://i.pravatar.cc/150?u=\(user.id)")!
                let (data, _) = try await URLSession.shared.data(from: url)
                return (user.id, data)
            }
        }
        var out: [Int: Data] = [:]
        for try await (id, data) in group { out[id] = data }
        return out
    }
}

6.4@MainActor and view models

@Observable
@MainActor
final class FeedViewModel {
    var posts: [Post] = []
    var phase: Phase = .idle
    enum Phase { case idle, loading, loaded, failed(String) }

    func load() async {
        phase = .loading
        do {
            posts = try await PostAPI.fetch()
            phase = .loaded
        } catch {
            phase = .failed(error.localizedDescription)
        }
    }
}
Cancellation is free, but only if you cooperate. The .task modifier auto-cancels when the view disappears. Inside long loops, call try Task.checkCancellation().

7.1Define a model with @Model

import SwiftData

@Model
final class TodoItem {
    var title: String
    var isDone: Bool
    var createdAt: Date
    var dueDate: Date?
    @Relationship(deleteRule: .cascade) var subtasks: [Subtask] = []

    init(title: String, dueDate: Date? = nil) {
        self.title = title
        self.isDone = false
        self.createdAt = .now
        self.dueDate = dueDate
    }
}

@Model
final class Subtask {
    var title: String
    var isDone: Bool
    init(title: String) { self.title = title; self.isDone = false }
}

7.3Query, insert, delete

struct TodoListView: View {
    @Environment(\.modelContext) private var ctx
    @Query(sort: \TodoItem.createdAt, order: .reverse) private var items: [TodoItem]
    @State private var newTitle = ""

    var body: some View {
        List {
            ForEach(items) { item in
                HStack {
                    Button { item.isDone.toggle() } label: {
                        Image(systemName: item.isDone ? "checkmark.circle.fill" : "circle")
                    }
                    Text(item.title).strikethrough(item.isDone)
                }
            }
            .onDelete { idx in idx.forEach { ctx.delete(items[$0]) } }
        }
        .safeAreaInset(edge: .bottom) {
            HStack {
                TextField("New todo", text: $newTitle)
                Button("Add") {
                    ctx.insert(TodoItem(title: newTitle))
                    newTitle = ""
                }.disabled(newTitle.isEmpty)
            }.padding()
        }
    }
}

Week 9 · Canvas, Shapes & Custom Drawing

From Path to Canvas to TimelineView — when you need pixels, SwiftUI delivers.

9.1Custom Shape

struct ChevronShape: Shape {
    var arrow: CGFloat = 12
    func path(in rect: CGRect) -> Path {
        var p = Path()
        p.move(to: .init(x: rect.minX, y: rect.minY))
        p.addLine(to: .init(x: rect.maxX - arrow, y: rect.minY))
        p.addLine(to: .init(x: rect.maxX, y: rect.midY))
        p.addLine(to: .init(x: rect.maxX - arrow, y: rect.maxY))
        p.addLine(to: .init(x: rect.minX, y: rect.maxY))
        p.closeSubpath()
        return p
    }
}

9.2Canvas — for high-volume drawing

struct StarfieldView: View {
    let stars = (0..<200).map { _ in CGPoint(x: .random(in: 0...1), y: .random(in: 0...1)) }
    var body: some View {
        Canvas { ctx, size in
            for s in stars {
                let r = CGFloat.random(in: 0.4...1.6)
                let p = CGPoint(x: s.x * size.width, y: s.y * size.height)
                ctx.fill(Path(ellipseIn: CGRect(x: p.x, y: p.y, width: r*2, height: r*2)),
                         with: .color(.white.opacity(.random(in: 0.3...1))))
            }
        }
        .background(.black)
    }
}

Week 10 · Architecture & Modularization

MV vs MVVM in SwiftUI, the Coordinator question, and Swift Package modular layouts.

10.1The honest take on MVVM in SwiftUI

SwiftUI's View already is a view-model in the Rx sense — it's a function from state to UI. With @Observable, a "ViewModel" is often just a data store you pass in or read from @Environment. Don't add ceremony for its own sake. Reach for VM when:

  • You have non-trivial transforms over async data streams.
  • You need to unit-test logic without rendering views.
  • Multiple platforms (iOS + macOS) share business logic.

10.2A pragmatic file/module layout

App/
  AppEntry.swift              // @main, root scene
Features/
  Feed/
    FeedView.swift
    FeedModel.swift           // @Observable
    FeedAPI.swift
  Profile/...
Core/
  Networking/                 // SPM module
  Persistence/                // SPM module
  DesignSystem/               // SPM module — colors, typography, components
Shared/
  Models/
  Extensions/

10.3Coordinators — needed?

Usually not. NavigationStack(path:) + a simple Router object covers most needs. Consider a coordinator only when you have multiple flows that own their own back stack (e.g., a deep onboarding tree that should not intermix with the main app's history).

Text(article.title).accessibilityAddTraits(.isHeader)

VStack { Text(name); Text(role) }
    .accessibilityElement(children: .combine)    // one a11y node, not two
The non-negotiable a11y trio: Dynamic Type (Text uses semantic styles), VoiceOver labels on every interactive element, and 4.5:1 minimum contrast. Audit each weekly project against this.

Week 12 · Capstone

Ship a real app that ties everything together.

12.1Pick one of these capstone briefs

  • Trail — a hike tracker. CoreLocation streams, MapKit overlay, SwiftData persistence, share sheet export, widget.
  • Brew — a coffee log. SwiftData with photos, recipe sharing via JSON, widget showing today's brew, watchOS companion.
  • Clip — a shared shopping list. CloudKit sync, real-time updates, optimistic UI, push notifications.

12.2Required capabilities (whichever brief you pick)

  • Networking with proper error/loading/empty states.
  • SwiftData persistence with at least one relationship.
  • One non-trivial custom layout or animation (Week 5 / 9 territory).
  • Modularized: at least one feature in a Swift Package.
  • Test target with one VM unit test and one UI test.
  • A11y pass: VoiceOver, Dynamic Type, RTL.
  • App icon + at least one App Intents shortcut.

12.3Definition of done

You can hand the device to a stranger, give a one-sentence pitch, and they can complete the primary flow without instruction. That is when you're done — not when the feature list is checked off.

Submission

Push the capstone to a public GitHub repo with a README that includes screenshots, the architecture sketch, and a "What I'd change next" section. That last section is the most important — it shows you're past the tutorial phase.
